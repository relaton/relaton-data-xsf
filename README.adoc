= XSF Publications Bibliographic data for Relaton-XSF

The Relaton-XSF project is a part of the Relaton project. It is a set of tools for processing bibliographic data in XML format. The project is hosted on GitHub.

The data source is https://xmpp.org/extensions/refs/.

This repository uses the XSF flavor of the
https://github.com/relaton/relaton[relaton] gem to fetch the documents, and runs
daily. `relaton-xsf` no longer exists as a gem of its own -- the flavor lives in
the combined `relaton` gem. `crawler.rb` parses the source above and stores the
documents in the `data` directory.

Branch `v2` is the published branch: relaton reads the data and the index from
it directly.

== Indexes

Two indexes are published. `relaton/support`'s shared `crawler.yml` zips and
commits both; nothing in this repository zips.

`index-v2`:: The current, pubid-keyed index, 520 rows. Written by
`Relaton::Xsf::DataFetcher` itself, with each row's `:id` a
`Pubid::Xsf::Identifier` serialised to its `_type: pubid:xsf:xep` hash. An XEP
identifier is a publisher and a number -- no edition, no date, no part -- so
there is one row per XEP and the ids are unique.

`index-v1`:: The legacy index, plain strings, 520 rows, kept alive for every
released `relaton` line that still reads `index-v1.zip` from this branch. The
gem no longer writes it, so `crawler.rb` builds it here through
`build_index_v1.rb`.

`index-v1` is built from the crawled documents in `data/`, not derived from the
`index-v2` beside it. It therefore does not depend on what pubid accepts, and it
has always held all 520 rows -- including `XEP README` and `XEP xxxx`, the XMPP
repository's `README` and its `xep-xxxx` template, which reach the indexer as
docids and are not documents. Older pubid revisions rejected both, so `index-v2`
held 518; the current one parses them, so it holds 520 too. `CLAUDE.md` records
the full history and why the fetcher guards that parse.

Run the specs that guard the build with:

[source,sh]
----
bundle exec rspec
----

== Dependency pins

`Gemfile` carries a **temporary path pin**, `gem "relaton", path: "../relaton"`,
because the XSF `index-v2` work is not committed in relaton/relaton yet. It
resolves only where the relaton checkouts are siblings, so **the Crawler
workflow cannot resolve it** and stays red until it reverts to
`git: "https://github.com/relaton/relaton.git", branch: "main"`. The Pages
build is unaffected -- it uses a Gemfile of its own.

`pubid` is pinned separately, and has to be: bundler reads a path or git gem's
gemspec, never its Gemfile. `Gemfile.lock` is git-ignored, so a crawl resolves
both fresh. See `CLAUDE.md`.

== Browsable index

The `data/` directory is published as a browsable, crawler-indexable index at
https://relaton.github.io/relaton-data-xsf/.

`.github/workflows/deploy.yml` calls relaton/support's shared
`data-deploy.yml`, which builds the page with `relaton index` (relaton-cli
reads `data/` directly) and deploys it to GitHub Pages. The index files are not
used by that build.
